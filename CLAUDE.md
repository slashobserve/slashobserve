# SlashObserve

SlashObserve is an agentic Grafana replacement: an engineer types `/observe checkout health by pod, last 6h` and gets a live, Grafana-style dashboard, then refines it in plain language.
Every change is a saved version.
This repository is the Community Edition monorepo (Apache-2.0), Go module `github.com/slashobserve/slashobserve`.
The product brief lives outside this repository, at `../docs/BRIEF.md` in the SlashObserve workspace; read it for background, but this file carries every convention needed to work here.

## Commands

| Command | What it does |
| --- | --- |
| `make build` | Install web dependencies, build the Vite app into `internal/server/webdist`, then build `bin/slashobserve-server` with the UI embedded. |
| `make server` | Build only the Go binary, embedding whatever is in `internal/server/webdist`. |
| `make cli` | Build only `bin/observe`; `make build` builds it too. |
| `make test` | `go test -race ./...` for the root module and `demo/shop`, then the web Vitest suite. |
| `make lint` | golangci-lint (config verify, format diff, run), `sqlc diff`, web typecheck, Spec drift and fixture parity check, web API type drift check (`api:check`), ESLint, knip (unused web files, exports and dependencies), Prettier check. |
| `make ci` | `lint`, `test`, `tidy-check` (`go mod tidy -diff` for the root module and `demo/shop`), `build`: what the CI `check` job runs. |
| `make generate` | Regenerate sqlc code, the web Spec types/validator and the web API types (`web/src/api/schema.gen.ts`) after editing migrations, queries, the schema or `api/`. |
| `make golden` | Rewrite the `pkg/grafana` corpus goldens (`go test ./pkg/grafana -run TestCorpusGoldens -update`). |
| `make demo` / `make demo-down` | Run the full demo stack in `deploy/compose` and stop it: the app on http://localhost:8080, Prometheus on http://localhost:9090 and the shop fault API on http://localhost:8081, with Dex, Postgres, ClickHouse, the OTel Collector, node-exporter, cAdvisor and the shop behind them. |
| `make demo-reset` | Stop the demo stack and drop its volumes, so the 26 hour request and latency backfill runs again on the next `make demo`. |
| `make demo-fault TYPE=errors\|latency PCT=N` | Inject a fault into the `checkout-0` pod through the shop fault API. |
| `make demo-fault-reset` | Clear the injected fault. |
| `make e2e` | Reset and boot the isolated `slashobserve-e2e` stack on http://localhost:18080 and run `scripts/e2e.sh`; the stack is left running. |
| `make e2e-browser` | Reuse the running, healthy e2e stack or boot one, then run Playwright in `web/e2e`; reuse does not rebuild, so rerun `make e2e` after code changes. |
| `make e2e-all` | Both suites, as CI runs them. |
| `scripts/e2e.sh down` | Tear the e2e stack down, including volumes. |
| `make evals EVALS_ARGS=...` | Run the eval runner (`go run ./evals/runner`) against a stack with a real LLM provider; needs `OBSERVE_SERVER` and `OBSERVE_TOKEN` (a service-account key) in the environment. |

Web-only commands run from `web/`: `bun run dev` (Vite on :5173, proxying `/api`, `/healthz` and `/readyz` to :8080), `bun run typecheck`, `bun run lint`, `bun run format`, `bun run test`.

## Layout

Directories are created when their phase starts; this is where things go.

- `cmd/slashobserve-server/`: server binary (`healthcheck` subcommand backs the Docker health check).
- `cmd/observe/` + `internal/cli/`: the `observe` CLI, including `observe comments list|reply|resolve` and `observe run [name...]` (runs a shared saved prompt by name like a prompt, or lists them) and `observe import <file>` (a Grafana import through `POST /api/v1/imports`, on a 120 s client; `--folder <title>` sets the request's `folder`, and the `Folder:` line and any folder note go to stderr so stdout stays the dashboard address, with `-q` hiding the `Folder:` line but never the folder note; API client with a service-account key; settings from flags, `OBSERVE_SERVER`/`OBSERVE_TOKEN`, then `~/.config/slashobserve/cli.json`; the saved key goes only to the server it was saved for).
- `internal/config/`: the only reader of `SLASHOBSERVE_*` environment variables.
- `internal/logattrs/`: turns an error into log attributes that are safe to write (the innermost Go error type, for a Postgres error the SQLSTATE, and for a system error the `errno` text) without its message, which can echo queries, tool results or credentials; not test-only, and used by every server log line that reports an error.
- `internal/logtest/`: test-only capture logger and assertions for log lines (see the Logging convention).
- `internal/db/`: pgx pool, goose migrations (`migrations/`), sqlc queries (`queries/`) and generated code (`dbsqlc/`); `dbtest/` starts one Postgres testcontainer per test binary and hands each test its own migrated database (`dbtest.Main` in `TestMain`, `dbtest.New(t)`, or `dbtest.NewWithLogger(t, logger)` to capture the DB's own log lines; skipped under `-short`).
- `internal/tctest/`: test-only retry for testcontainers starts that fail on testcontainers-go v0.44.0 reaper (ryuk) start errors: the shared-reaper lookup race and ryuk dying while it starts; every container start in tests goes through it.
- `internal/clientgone/`: the one mapping for a caller that went away mid-request (a `context.Canceled` error while the request context is itself done): status 499, no body, a debug line, never an ERROR; a handler's error-to-500 path calls it first.
- `internal/auth/`: OIDC login, sessions, service-account keys, the auth middleware and the instance roles: `Role` (Viewer < Commenter < Editor < Admin), `ResolveRole` (the one precedence rule), `groupsClaim`, `RequireRole` and `Routes`, through which every `/api/v1` route is registered with its lowest role.
- `internal/forbidden/`: the one definition of the `forbidden_role` code and its two 403 texts (`RoleMessage`, `AccessMessage`), a leaf package so the CLI can compare against them without linking the server; every HTTP handler that answers these 403s uses it.
- `internal/users/`: the People routes (`GET /api/v1/users`, paged newest first sign-in by `(created_at, id)`, `PATCH /api/v1/users/{id}`, which sets or clears (`null`) the role an Admin chose and answers 409 `role_locked` or `last_admin`, and `DELETE /api/v1/users/{id}/sessions`, which also expires the caller's cookie when they sign themselves out), all Admin only (`auth.RoleAdmin`) and for people only (`auth.RequireUser`).
- `internal/folders/`: folders, folder permissions and the one place that decides who sees and changes a dashboard.
  `LevelFor` (instance role plus a folder's facts: restricted, the caller's grants, creator) gives a level (none, view, comment, edit, admin) and `AbilitiesFor` turns it into view, comment, edit, manage and create; both are pure and unit-tested, and the rule is written under "Folders and access" in the backend conventions.
  `Access` loads the facts for a principal in one query (`Levels`) and answers for a dashboard (`Dashboard`), a folder (`Folder`), where a new dashboard goes (`CreationFolder`) and where an import goes (`ForImport`); `RequireDashboard(need)` and `RequireFolder(need)` are the route middleware.
  List queries filter by `Levels.Visible()` and fail closed (an empty list shows nothing); services check writes themselves; every HTTP route keyed by a dashboard id declares `RequireDashboard`.
  Its `Handler` serves `GET|POST /api/v1/folders`, `GET|PATCH|DELETE /api/v1/folders/{id}` and `GET|PUT /api/v1/folders/{id}/permissions` (`PUT` replaces all entries, at most 50, each a `user_id`, `email` or `group` with a level `view|comment|edit|admin`).
- `internal/egress/`: the only fetcher of user-supplied URLs: allowlisted hosts only, https on port 443, public addresses only (checked at dial), redirects rechecked hop by hop, no cookies or credentials, size and time limits, a 15 minute cache whose bodies are copied per caller.
- `internal/egress/allowlist/`: the `outbound_domains` table, `GET|POST /api/v1/outbound-domains` and `DELETE /api/v1/outbound-domains/{domain}` (GET for any signed-in person, POST and DELETE for Admins, and keys are refused on all three; 100 entries; deny-all when empty), and the `SLASHOBSERVE_OUTBOUND_DOMAINS` lock (`none` or a list; the table is then neither read nor written and changes answer 409 `managed_by_config`).
- `internal/prompts/`: saved prompts (`saved_prompts` table), `GET|POST /api/v1/prompts` and `PATCH|DELETE /api/v1/prompts/{id}`: a prompt is a name and plain text owned by a person, private or shared with everyone; the list shows the caller's own prompts then shared ones by name (at most 500; a key sees shared prompts only), `?name=` resolves one ignoring case (own first, then shared; longer than 64 characters is 400 `invalid_request`); names are unique per owner and among shared prompts, 100 per person; `CanEdit` is the only edit rule (the Editor role or above, and the owner, or an Admin on a shared prompt), GET is registered at Viewer, and POST, PATCH and DELETE at Editor for people only (keys are refused).
- `internal/origin/`: the origin of a request (`web`, `cli`, `mcp` or `api`) and the cleaned MCP client name, carried in the context and recorded on versions and agent requests.
- `internal/server/`: Gin HTTP server, routes, embedded web build (`webdist/`).
- `internal/server/mcp/`: remote MCP at `/mcp` (stateless Streamable HTTP, JSON responses), bearer service-account keys only, origin-checked; every tool comes from `internal/agent/tools`.
- `internal/queryproxy/`: panel query runner shared by save validation and the proxy: kind per query (instant flag, else instant for the types in `instantPanels` of `spec/schema/defaults.json` and range for every other type), panel `timeFrom`/`timeShift` applied to the range (`PanelRange`) for panel data, previews and save checks, step from maxDataPoints, variable defaults, a 32-call upstream semaphore, one error-to-HTTP mapping.
  An `alertlist` panel may save with an empty result (`query_empty` is not reported for it), because no firing alerts is a normal state.
  `DraftLimits` (15 s, 200 series, 100,000 points, 1,000 rows) apply to every query whose text did not come from a saved Spec (agent tools and the draft preview), and `CheckPanels` checks chosen panels of a Spec with the save rules.
- `internal/queryproxy/proxyhttp/`: the query proxy HTTP handlers (panel data, variable values, datasource lint, draft preview, names), registered as a `server.Registrar`; a subpackage because it reads versions through `internal/dashboards`, which imports `queryproxy`.
- `internal/ttlcache/`: the byte-bounded TTL LRU and the coalescing call group behind the query proxy's caches.
- `internal/datasource/{prometheus,clickhouse,macros,provision}`: the datasource core and adapters, query macros, and registry construction from config.
  A ClickHouse range query with `format` `table` or `logs` returns one frame with the columns and rows as selected; any other format, when the first column is a time column, splits rows into one series per combination of string columns, with that column renamed `Time`.
- `internal/llm/`: provider-neutral gateway (`Provider` starts a `Session` that owns the native history); adapters `anthropic/`, `openaicompat/`, `replay/`; `providers/` picks one from configuration.
  `e2e/fixtures/llm/` holds the replay fixtures.
- `internal/dashboards/`: dashboard and version storage, the save validation pipeline and the `/api/v1/dashboards` routes (`Service.Register`).
- `internal/httpapi/`: the HTTP helpers shared by `internal/dashboards` and `internal/revisions` (error responses, the 422 `invalid_spec` body, body decoding, path and limit parameters, time formatting, the `(time, id)` cursor codec).
- `internal/events/`: the event payload, the `slashobserve_events` Postgres channel name shared by publishers and the SSE stream, and the `Broker` that fans notifications out to subscribers; `internal/events/stream/` serves them over SSE.
- `internal/revisions/`: the durable agent request queue (`agent_requests`), its in-process workers, the `Reviser` contract the agent implements (`agent.Reviser`) and the `/api/v1/dashboards/{id}/revisions` routes.
- `internal/imports/`: Grafana imports (`imports` table): preview, the tolerant first save through `dashboards.Service.CreateImported`, the list and the per-dashboard record, with 1 import in flight per principal and 4 per instance, and 2 previews per principal and 4 per instance, each pool refusing with `ErrBusy`; `original` is stored once and never selected.
  Its `Handler` serves `POST /api/v1/imports/preview`, `POST /api/v1/imports` (201 with `Location`, 422 `datasources_unresolved` while a source datasource has no match, 429 `too_many_imports`; the preview answers 429 too, from its own pool because converting a large dashboard costs memory), `GET /api/v1/imports` (filters `made_by=me` and `dashboard_id`) and `GET /api/v1/dashboards/{id}/import` (404 `not_imported`).
- `internal/news/`: `GET /api/v1/news`: fetches a feed through `internal/egress`, parses RSS 2.0, RSS 1.0 and Atom, and returns plain-text items with absolute http(s) links or null.
- `internal/agent/tools/`: the only place agent tools are defined (19 tools, sorted, constant schemas; 15 for the built-in agent, since the 4 `MCPOnly` tools (the comment tools and `list_folders`) are left out of what `agent.New` sends to the model; every tool has a `MinRole`, which `Call` enforces for keys and skips inside an agent run, whose requester was checked at enqueue and claim); `import_grafana_dashboard` (the same import as `POST /api/v1/imports`, sharing its service and in-flight limits) counts as a save in the agent loop, so a successful import ends an `/observe` run with that dashboard, and the agent may import only Grafana JSON that the request prompt contains; `Call` returns a tool error the model can fix or an internal error; ad-hoc queries run through the panel runner with tool limits.
- `internal/agent/`: the loop (discover, draft, lint, save, up to 3 repairs; a successful save ends the run); a run's only product is a Spec saved through `internal/agent/tools`; a revise conflict restarts once from the latest version.
  In suggest mode (a `suggest` agent request) the run's only product is one proposed panel: `update_dashboard` places the panel with the run's id into the requested version (with the user's draft), validates it with `spec.Parse` and the save rules for that panel, and returns it without saving; write tools other than that refuse.
  The agent, and any MCP client, may move or delete a placeholder panel but never create or edit one; `create_dashboard` and `update_dashboard` reject that with `placeholder_not_allowed` before saving.
- `internal/agent/prompts/`: embedded prompts, including the system prompt and the Spec authoring guide, and `Schema()`, the schema the model reads (the frozen schema with its `$schema`, `$id`, `title` and `description` annotations removed and the validation keywords untouched, minus every property and `anyOf`/`oneOf` branch marked `"x-omitFromPrompt": true`, which holds values only imports need, and the marker itself; a marked key is never required), used by the system prompt and by `get_spec_guide`; a rule that lives only in a schema description belongs in the guide.
- `evals/`: scenarios (`scenarios/*.yaml`), pricing, and the runner (`go run ./evals/runner`), which scores validity, data, source, metrics, tables, units, panel count, thresholds and latency through the public API and reports cost; scenarios tagged `replay-smoke` run in e2e with replay fixtures.
  A scenario's `expect` takes `datasources`, `metrics`, `tables`, `units` (ids from the Spec unit enum), `min_panels`, `max_panels`, `max_seconds`, `thresholds`, and three optional feature checks: `query_contains_any` (a list of groups; each group needs at least one alternative to appear, case and whitespace insensitive and on word boundaries, in some panel query; PromQL `#` comments are ignored), `time_range_from` (accepted values of the dashboard's `time.from`) and `threshold_at` (unit to threshold value, matched on a single panel).
  The runner holds a slot per scenario until its request finishes server-side (a timed-out request is polled for up to 3 minutes) and retries a 429 on create, so `--parallel` stays within the server's 3 active observe requests per key and is capped at 3.
- Later: `pkg/extension`, `deploy/helm/`.
- `spec/schema/observespec.v0.json` is the ObserveSpec source of truth: the evolved v0 frozen for milestone 1 (same `$id` and `specVersion` as before): the frozen input plus the 200-panel cap (root `panels.maxItems` and its description, `rowPanel.panels.maxItems`) plus the panel types Ishan signed off on 2026-10-27 (every Grafana built-in type SlashObserve can back, with `dashlist` as a static panel, and `news` as a static panel added under his 2026-10-29 ruling), plus the dashboard `cursorSync` field (`off`, `crosshair`, `tooltip`; Grafana's `graphTooltip`) he signed off on 2026-10-29, plus `${name}` datasource references to declared datasource variables (milestone 2 decision 6, signed off 2026-10-29), and never edited without his sign-off; `spec/examples/` holds valid examples and `invalid/` fixtures with `expected.json`, shared by Go, TS and e2e tests.
- `pkg/spec/` (public): hand-written types checked against the schema by a conformance test; `Parse` is the only validation entry point, accepts only the evolved shape and returns `*ValidationError` with JSON-Pointer issues; `Upgrade` is the pure rewrite of the legacy v0 shape (`timeRange`, `{type, uid}` datasources, panel `query` and `legend`) to the evolved one, for migrating stored versions and converting fixtures; `ScanQuery` and `Macros` define query reference syntax for the macros package, including Grafana's globals (`$__interval_ms`, `$__range_s`, `$__range_ms`, `$__from`/`$__to` with `date` formats, `$__dashboard`, `${__user.login|email|name|id}`); ClickHouse queries also take the official plugin's macros (`$__timeFilter_ms`, `$__dateFilter`, `$__dateTimeFilter`/`$__dt`, `$__fromTime`, `$__toTime`, their `_ms` forms, `$__interval_s`, `$__timeInterval`, `$__timeInterval_ms`, `$__conditionalAll`), and `$__conditionalAll` is the only macro whose arguments hold references, exposed as `Reference.Nested`; `Diff` returns a stable structural change list between two Specs (panels and row children matched by `id`, variables by `name`, queries by ref, overrides by their match written as `<kind>:<value>`, transforms by position while their count is unchanged) for version history. A dashboard holds at most 200 panels, row children and rows included (`spec.MaxPanels`).
  Panels are flat structs covering every panel kind; `AllPanels` and `FindPanel` walk top-level panels and row children with their JSON Pointers, `DataPanels` and `FindDataPanel` narrow that to the panels that run queries, and `QueryRef` gives a query's ref (`A`, `B`, ... by position unless written).
  `WithPanel` places a draft panel into a dashboard at the position of an existing panel and parses the result, so a draft is always judged inside its dashboard.
  The draft gets the same byte-level checks as `Parse` (UTF-8, surrogates, duplicate keys, depth, trailing data), reported under the panel's pointer; on a row it replaces the row and all its children.
- `pkg/grafana/`: the Grafana importer (pure: no network, no database): `Detect`, `Convert` (Spec, source datasources with matches, report) and `Result.Verify`; `testdata/corpus/` holds the golden corpus with its sources and licences.
  A Grafana option is handled in this order: converted when the Spec has the field; else silent only when it equals a Grafana default (`grafanaDefaults`) or is listed in `cosmeticOptions` with the renderer behaviour that makes it invisible; else reported as a path.
  A panel, query or variable that uses a Grafana datasource variable keeps it as `${name}` and the variable's matched datasource becomes its `default` (a `${DS_*}` reference declared in `__inputs` is pinned to its match, as Grafana's import does); if the datasource variable cannot be imported, its references fall back to the match with a dashboard note, and a panel lists at most 100 paths.
  A min step written as a variable imports as `${name}`, a single-select custom variable of durations used as a min step imports as an interval variable, and `intervalFactor` 2 to 10 is kept.
  Grafana's renamed and retired panel types import as their modern type (`graph`, `table-old`, `singlestat`, `grafana-singlestat-panel`, `datagrid`, `logs-new`, `logstable`, `grafana-piechart-panel`), and `annolist`, `welcome`, `gettingstarted`, `debug`, `live` and `alertGroups` become placeholders with their own reason.
  `grafana-worldmap-panel` imports as `geomap` and `natel-discrete-panel` as `state-timeline`.
  Alert lists import as one Prometheus `ALERTS` query, and Grafana-managed or legacy ones become placeholders.
  Canvas element positions are converted to percent of the panel and reported, and no element link or action is imported.
  A dashboard list is a static panel and never needs a datasource match.
  A news panel imports its `feedUrl` (http upgraded to https and reported; empty means Grafana's own blog feed, `https://grafana.com/blog/news.xml`); `showImage` and `useProxy` are dropped silently.
  ClickHouse trace queries (`queryType` `traces`, `format` 3) import as `table` queries.
  A time series, trend or legacy graph legend imports its table or list mode (`legendMode` is written only where Grafana's mode differs from what `legendValues` implies), sort, width and hidden series; a table legend on a bar chart, pie chart or XY chart is still reported.
  Goldens are reviewed diffs: run `make golden`, read every changed golden, and say in the commit message which converter rule changed them.
  `TestCorpusRatio` holds the gate: at least 90% of corpus panels are imported or partial, and a floor: the share of fully imported panels never drops below `minimumFull` (39.1% today); raise the constant when the share grows, and lower it only when new corpus files change the denominator. The test fails when the measured share exceeds the floor by 0.5 points or more and prints the value to set, so a converter change that raises the share raises the floor in the same commit.
- `api/`: the OpenAPI document for `/api/v1`: `openapi.yaml` holds the root, shared schemas and responses, and each feature adds `paths/<feature>.yaml` plus one `$ref` line in the root; `api.Load` embeds and validates it.
- `web/`: React app (Bun); `web/src/routes` (TanStack Router files), `web/src/shell` (the sidebar shell), `web/src/components/ui` (shadcn), `web/e2e` (Playwright).
- `deploy/compose/compose.yaml`: the one compose stack; `scripts/e2e.sh`: e2e stack lifecycle and API smoke suite.
- `docs/`: the operator guide, one page per topic under `get-started/`, `connect/`, `use/`, `teams/`, `concepts/`, `operate/` and `reference/`, each with `title` and `description` front matter and no `#` heading, linking other pages by relative `.md` path; the website orders the sidebar; update the page that covers a setting, default or behavior in the same change as the change.
- `demo/shop/`: its own Go module (`github.com/slashobserve/slashobserve/demo/shop`) with the `serve`, `loadgen` and `healthcheck` commands; it emits the demo metrics, logs and traces.
- `deploy/compose/{prometheus,clickhouse,otelcol}/`: the configs mounted into the demo stack's Prometheus, ClickHouse and OTel Collector.
- `tools/<tool>/go.mod`: pinned Go dev tools (sqlc, golangci-lint).

## Backend conventions

- Configuration: every setting is an environment variable named `SLASHOBSERVE_*`, parsed and validated only in `internal/config` (`config.Load`).
  Current settings: `SLASHOBSERVE_HTTP_ADDR` (default `:8080`), `SLASHOBSERVE_DATABASE_URL` (required), `SLASHOBSERVE_LOG_LEVEL` (`debug|info|warn|error`, default `info`), `SLASHOBSERVE_LOG_FORMAT` (`json|text`, default `json`).
  Auth settings: `SLASHOBSERVE_PUBLIC_URL` (required; http or https origin with no path, query or user info), `SLASHOBSERVE_OIDC_ISSUER_URL` (required; used exactly as given because issuer comparison is exact), `SLASHOBSERVE_OIDC_INTERNAL_URL` (optional origin the server's back-channel uses instead of the issuer's scheme and host), `SLASHOBSERVE_OIDC_CLIENT_ID` and `SLASHOBSERVE_OIDC_CLIENT_SECRET` (required), `SLASHOBSERVE_SESSION_TTL` (default `168h`, between `5m` and `720h`), and `SLASHOBSERVE_AUTH_ALLOWED_EMAIL_DOMAINS`.
  `SLASHOBSERVE_AUTH_ALLOWED_EMAIL_DOMAINS` is required: a comma-separated list of domains matched exactly against the verified email's domain, or `*` as an explicit allow-all that logs a startup warning.
  `SLASHOBSERVE_ADMIN_EMAILS` is optional: comma-separated addresses (lowercased, at most 100) that are always Admins; unset, the earliest-created user is the Admin.
  `SLASHOBSERVE_OIDC_GROUP_ROLES` is optional: comma-separated `group=role` entries (split on the last `=`, role `admin|editor|commenter|viewer`, at most 100) that map the ID token's `groups` claim to a role.
  `SLASHOBSERVE_AUTH_PROVIDER_NAME` is optional: the identity provider's display name (trimmed, at most 64 characters, default empty), shown to signed-in clients as `oidc_provider_name`; the demo and e2e stacks set it to `Dex`.
  `SLASHOBSERVE_DATASOURCES_FILE` is optional: a YAML file listing datasources, and unset means none.
  `SLASHOBSERVE_OUTBOUND_DOMAINS` is optional: unset leaves the outbound allowlist to Settings, `none` or a comma-separated list of domain patterns locks it (at most 100, validated by `domains.ParsePattern`).
  The file never holds a secret: passwords and tokens are referenced by `passwordEnv`, `bearerTokenEnv` or `headersFromEnv` (a map of header name to variable name) names that start with `SLASHOBSERVE_`, or by `passwordFile`, `bearerTokenFile` or `headersFromFile` paths.
  An env name the server's own config reads (such as `SLASHOBSERVE_DATABASE_URL`) is refused, and a header name may appear in only one of `headers`, `headersFromEnv` and `headersFromFile`.
  The file needs a top-level `datasources` key and one YAML document; unknown fields are rejected, and `deploy/compose/datasources.yaml` is the exemplar.
  An empty list logs a startup warning.
  LLM settings are all optional: `SLASHOBSERVE_LLM_PROVIDER` (`anthropic|openai|replay`; unset means no agent, so the revision and observe endpoints answer 503 `agent_unavailable`) and `SLASHOBSERVE_LLM_MODEL` (default `claude-sonnet-5-5` for `anthropic`, required for `openai`, ignored by `replay`).
  `SLASHOBSERVE_LLM_API_KEY` or `SLASHOBSERVE_LLM_API_KEY_FILE` (at most one; required for `anthropic`, optional for `openai`) supplies the credential, and `SLASHOBSERVE_LLM_BASE_URL` (absolute http or https URL, a path is allowed) overrides the provider endpoint.
  `SLASHOBSERVE_LLM_EFFORT` (`low|medium|high|xhigh|max`, default `medium`, Anthropic only), `SLASHOBSERVE_LLM_MAX_TOKENS` (`1024` to `64000`, default `16000`) and `SLASHOBSERVE_LLM_REQUEST_TIMEOUT` (`10s` to `10m`, default `120s`) bound each model call.
  `SLASHOBSERVE_LLM_REPLAY_DIR` is required for `replay`.
  The LLM API key is never logged or echoed in an error.
  Never log secret values, the database URL and the OIDC client secret included.
  `SLASHOBSERVE_API_CONTRACT_CHECK` (`true|false`, default `false`) is for the e2e stack only: it validates every `/api/v1` request and response against `api/openapi.yaml`, and never belongs in production.
- HTTP: Gin, assembled in `internal/server.New`.
  JSON API under `/api/v1`; `/healthz` is liveness with no dependencies; `/readyz` is readiness (database ping and no pending migrations).
  Every other GET is the SPA: build files from the embedded `webdist`, `/assets/*` cached as immutable, unknown `/api/*` paths get a JSON 404, missing `/assets/*` files and missing top-level names with an extension (like `/robots.txt`) get 404, and every other path gets `index.html`.
  Responses forbid framing (`X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'`).
- MCP: `/mcp` is mounted through `server.Options.Mounts` outside `/api/v1`, so the API contract check does not cover it.
  It accepts only `Authorization: Bearer` service-account keys (a session cookie is ignored), refuses an `Origin` other than `SLASHOBSERVE_PUBLIC_URL`, answers 413 above 8 MiB, 429 above 8 in-flight requests per principal and 503 `busy` above 32 in flight across all principals, and keeps no session state (the `Mcp-Session-Id` it sets on `initialize` only carries the client name).
  Comment tools (`list_comments`, `reply_to_comment`, `resolve_comment`) are MCP-only: `agent.New` leaves them (`Tool.MCPOnly`) out of the model's tool list and a call made inside an agent run is rejected with `invalid_request`, because the server answers and resolves threads after a run; they never queue revisions.
  `list_folders` is MCP-only too: it lists the folders the key can see with `can_create`, and `create_dashboard` takes its ids as `folder_id` (default: the folder the key last created a dashboard in, else General).
  A tool's floor is its `MinRole`, checked when the tool is called, not when tools are listed: Viewer for `list_dashboards`, `get_dashboard`, `get_spec_guide`, `list_comments` and `list_folders`; Commenter for `reply_to_comment` and `resolve_comment`; Editor for the other 12.
  A refusal is a tool error `forbidden_role`, and a dashboard or folder the key cannot see is `not_found`.
  Connect Claude Code with `claude mcp add --transport http slashobserve http://localhost:8080/mcp --header "Authorization: Bearer <key>"`.
  Admins create keys and copy Claude Code, OpenCode and CLI setup snippets on the web page `/keys` (API keys in the sidebar for Admins; `/settings/keys` redirects).
- Auth: every `/api/v1` route goes on the `auth.Routes` returned by `auth.Service.Mount` except `/api/v1/auth/*`; feature packages register through `Register(api auth.Routes)` and never see a raw gin group.
  Every `/api/v1` route is registered through `auth.Routes` with its lowest role (`auth.RequireRole`); handlers never check roles; refusals are 403 `forbidden_role`.
  `auth.RequireUser` stays a separate principal-kind check after the role, so a key cannot manage keys whatever its role.
  A user's role is `auth.ResolveRole` of the stored inputs, recomputed at each sign-in and for every user at boot (`ReconcileRoles`): `SLASHOBSERVE_ADMIN_EMAILS`, else the first user when that is unset, then the highest role mapped from the `groups` claim, then the role an Admin chose, else Editor; the first three (`RoleSource.Locked`) cannot be changed on the People page.
  The `groups` scope is requested only when discovery lists it in `scopes_supported`.
  Service accounts carry a `role` (default Editor) that their keys act with, and `auth.Service.Principal` re-reads a principal's current role.
  Handlers read the caller with `auth.FromContext`.
  Sessions and keys are opaque random tokens stored only as SHA-256.
  Cookie-authenticated mutations pass `http.CrossOriginProtection`.
  `users.last_seen_at` is touched at most once a minute (`userSeenInterval` is the only definition, passed to the query) by session requests that passed authentication and, for mutations, the cross-origin check.
  Errors are `{"error","code"}` and 401s carry `WWW-Authenticate: Bearer`.
  The issuer is the browser-facing URL, and `SLASHOBSERVE_OIDC_INTERNAL_URL` only rewrites the server's back-channel host.
  `GET /api/v1/instance` returns the public and MCP URLs, the issuer URL, the optional provider display name, allowed email domains and session TTL, never a secret or the internal OIDC URL.
- Folders and access: `internal/folders` is the only place that decides who sees and changes a dashboard, and every dashboard lives in exactly one folder (`dashboards.folder_id`, which defaults to General through `general_folder_id()`, so raw inserts land there).
  An instance Admin has the Admin level on every folder.
  A folder with no permission rows is open, and each person gets the level of their role: View for a Viewer, Comment for a Commenter, Edit for an Editor.
  A folder with rows is restricted and invisible to anyone who has no row (by user, or by a `groups` name) and did not create it; a hidden folder hides its dashboards everywhere.
  Whoever can see a restricted folder gets the higher of their role's level and their grants, capped by their role: a Viewer only views and a Commenter only comments whatever the grant says, and an Editor reaches Admin through an Admin grant or as the folder's creator.
  A grant never lowers access and never lifts a person above their instance role, so the same cap holds on every surface that reads `folders.LevelFor` (web, API, MCP, CLI and agent runs); stored rows are never rewritten when a role changes.
  Abilities follow the level alone: Comment needs Comment, Edit and Create (new dashboards and imports) need Edit, manage (rename, delete, permissions, folder Admin level) is Admin.
  Service accounts match no grant, because rows hold users and groups, so a key sees a restricted folder only as an Admin or as the creator (`created_by_kind` and `created_by_id`).
  General is never restricted, renamed or deleted, and a folder deletes only when empty (409 `folder_not_empty`).
  Titles are 1 to 100 characters and unique ignoring case (409 `folder_exists`).
  A dashboard in a folder the caller cannot see answers 403 `forbidden_role` ("you do not have access to this dashboard") on HTTP, a visible one with too low a level answers 403 `forbidden_role` ("your role does not allow this"), an invisible folder answers 404 `not_found`, and tools answer `not_found` for both.
  Moving a dashboard (`PATCH /dashboards/{id}` with `folder_id`) needs Edit on both folders and saves no version.
  An agent run is checked when it is enqueued (403) and again when a worker claims it, after reloading the requester: a requester that no longer exists fails the request with `agent_requester_gone`, and one that lost Edit on the dashboard (or the Editor role, for an `/observe` request) fails it with `agent_requester_forbidden`.
  The event stream re-reads the caller's access at every ping, with the role captured when the stream opened, and ends when the dashboard is no longer visible.
  An import goes to the request's `folder` title, else `meta.folderTitle` of an API-format Grafana export, else the caller's creation folder (the folder they last created a dashboard in, else General); titles match ignoring case, and a General, empty or invalid title means the creation folder.
  A missing folder is created for an Editor or Admin; a folder the caller cannot create in sends the dashboard to the creation folder with a `folder_note`.
  The folder is chosen or created before the dashboard saves, outside its transaction, so a failed save can leave an empty folder, and a concurrent create of the same title retries once.
  `import_grafana_dashboard` returns the chosen folder's title as `folder` next to `folder_note`.
- Origin: every saved version and agent request records `origin` (`web` for a session cookie, `cli` for a bearer key whose `User-Agent` starts with `observe/`, `mcp` for `/mcp`, `api` for any other bearer key) and, for MCP, `origin_client` from the request's `_meta` `io.modelcontextprotocol/clientInfo` or from the `so1.<random>.<base64url name>` `Mcp-Session-Id` label the server sets on `initialize`; names are cleaned and capped at 64 characters, and the client name is never logged.
  A version saved by the agent records the origin of the request that asked for it, and `agent_request_id` links the two.
  Origin is a display label and never an access decision; `internal/origin` owns it.
- Database: Postgres through a pgx v5 pool.
  Migrations are goose SQL files `internal/db/migrations/NNNNN_snake_case.sql` with `-- +goose Up` and `-- +goose Down`, numbered sequentially; never edit a merged migration.
  Migration 10 is a Go migration (`internal/db/specupgrade.go`, registered in `newMigrator`) that rewrites every stored Spec with `spec.Upgrade`; it has no file, so SQL file numbering skips `00010`, and a new SQL file takes the next number above both the highest file and every Go migration version; a file reusing a Go migration's version stops the server at boot.
  The server applies migrations at boot under a Postgres advisory lock.
  Queries live in `internal/db/queries`; sqlc generates `internal/db/dbsqlc` (committed, never hand-edited; run `make generate`).
- Dashboards: versions are immutable and linear (`parent_version = version - 1`); a save validates with `spec.Parse`, then runs every panel query through `internal/queryproxy`, outside any transaction; the conditional `latest_version` update is the concurrency check (409 `version_conflict`); events go out with `pg_notify` on channel `slashobserve_events` inside the saving transaction.
  `dashboard_versions.unverified` (NULL when empty) records the panels and variables whose queries failed but were kept; `CarryUnverified` in `internal/dashboards/unverified.go` is the only rule (used by `AddVersion`, `AddRequestVersion` and suggest mode): a failing panel or variable is kept only when the parent lists it and its queries (every field, effective datasource) and every variable they reach (by name and whole definition, through variable queries and regexes, plus adhoc variables on those datasources) are byte-equal; one that passes or is removed leaves the list, and restore copies the restored version's list.
  `dashboards.created_*` copy version 1 (author, origin, MCP client, `created_via` `direct` or `agent`) and never change; `dashboard_versions.datasource_uids` is a generated column from the SQL function `observespec_datasource_uids(spec)`, which reads the evolved Spec shape and sorts in byte order; a `${name}` reference is not a uid, so the function leaves it out and adds the `default` of each datasource variable that a reference names (a datasource variable without a default adds nothing); whenever the Spec moves datasources, change that function with `CREATE OR REPLACE` in a new migration that then runs `UPDATE dashboard_versions SET spec = spec` to recompute the stored column; `GET /dashboards` filters with `made_by`, `datasource`, `q`, `folder` (a folder id) and repeated `tag` (every given tag must match, backed by the GIN index `dashboards_tags_idx`), orders by `order=updated` (default) or `order=folder` (folders by title with General last, then newest first), and returns `total_count`; each dashboard carries its `folder` and the caller's `permissions` (`comment`, `edit`, `manage`, `create`); `GET /dashboards/tags` lists every tag with its dashboard count, by name, at most 500.
  The lists, the tag counts, the `dashboard_count` of `GET /datasources` and `GET /imports` count only dashboards in folders the caller can see.
- Events: writers `pg_notify` on `slashobserve_events` inside their transaction; one `events.Broker` per process listens and fans out to `GET /api/v1/dashboards/{id}/events` (SSE) per dashboard; every stream starts with `ready` (current `latest_version`), sends `resync` after a listener reconnect, pings every 15 s and ends at the first ping after the caller's session or key stops being valid or the caller can no longer view the dashboard (so a sign out closes open streams within 15 s) or after 2 consecutive failed credential checks, ends after 30 minutes, and clients refetch on `ready` and `resync` instead of replaying ids.
- Revisions: comments with `request_revision: true` (the default is false since milestone 1; replies never request revisions) and `POST /dashboards/{id}/revisions` prompts enqueue `agent_requests` rows, a comment's inside its own transaction (the prompt takes an optional `panel_id` that must exist in the latest version, 422 `unknown_panel`); at most 5 are queued or running per dashboard (429 `too_many_revisions`, enforced under a per-dashboard advisory lock).
  In-process workers (2 per process) claim under a global advisory lock with `FOR UPDATE SKIP LOCKED`, hold a 5 minute lease, run at most 2 attempts and run one request per dashboard at a time (a partial unique index allows one running row per dashboard, and a queued request waits behind an expired running one until it is retried or failed); wake-ups come from `pg_notify` on `slashobserve_agent_requests` plus a 5 s poll, and a run gets 3 minutes.
  `dashboard_versions.agent_request_id` is unique and the agent's `update_dashboard` saves through it, so a retried run returns the version it already created instead of a second one.
  A finished request keeps a status, `result_version` and an error of at most 500 characters taken only from the agent's own fixed messages, and every status change of a revision or observe request sends a `revision.updated` event (a `suggest` request sends none).
  A saved version always wins: before a failure is recorded, and when the lease sweep exhausts a request, the request counts as succeeded with that version if one exists under its id.
  `POST /dashboards/{id}/revisions` also takes `comment_id` (a thread or a reply, never together with `panel_id`; the request is stored with `source = 'comment'` against the thread's root and uses the thread's panel, 404 `not_found` when the dashboard has no such comment); when any request with a comment succeeds, the worker resolves the open thread in the same transaction with `resolved_by_version` = the saved version and the requester as resolver, and sends `comment.updated` (an already resolved thread is left alone, a failed or released request never touches it, and a resolution that errors runs in a savepoint, is logged as `agent_request_thread_resolve_failed` and skipped, so the request still records its success); the model never writes replies.
  The saved version's `version.created` arrives before the `revision.updated` that reports `succeeded`, and clients must not depend on the order between them.
  A shutdown cancels the running request and releases it back to the queue without spending an attempt, and so does a failed check for a saved version; only a crash leaves a lease to expire for the next process.
  Without an LLM provider prompts get 503 `agent_unavailable` and comments do not enqueue, so turning an agent on later never replays old comments.
  A `suggest` request (`POST /dashboards/{id}/suggestions`) proposes one panel and saves nothing: it is exempt from the one-running-per-dashboard rule (it neither blocks nor waits behind a revision) but shares the worker pool, does not count toward the cap of 5, is capped at 2 per principal and 10 per instance, sends no events, and is readable only by its requester and only at `GET /dashboards/{id}/suggestions/{id}`.
  The draft panel in a suggest body is at most 63 KiB (`spec.MaxSuggestedPanelBytes`, the same limit the agent's proposed panel has) as compact JSON once placed in the version, the request body is capped at 96 KiB, and the draft must hold no NUL character; it is placed into the requested version and validated there before anything is queued (422 `invalid_spec` with `issues`, 422 `unknown_panel` for a panel that is not a data, text or dashboard list panel).
- Observe requests: `POST /api/v1/observe` enqueues an `agent_requests` row with `source = 'observe'` and no dashboard (at most 3 queued or running per principal, 429 `too_many_requests`, and 20 per instance, 429 `agent_busy`), or, with `dashboard_id`, a follow-up revision with `source = 'prompt'`.
  Observe rows never block each other in the claim; `dashboard_id` is filled from the version saved under the request id when the request finishes, so queue lookups of a saved version use the request id only.
  `create_dashboard` saves through `dashboard_versions.agent_request_id`, so a retried run returns the dashboard it already created.
  `GET /api/v1/observe/{id}` returns any agent request that has a dashboard, and one without a dashboard (an `/observe` request still running or failed) only to its requester, 404 `not_found` to anyone else, with progress `steps` (the tools' fixed step strings, at most 100 per attempt, tagged by attempt) and `usage` (tokens, model calls and repair rounds of the finishing attempt, null when the run made no model call); a shutdown release deletes the released attempt's steps and the re-claimed run reuses its attempt number, so clients tell a restarted list by each step's `at`, not by `attempt` alone; the `observe` CLI polls it every second, rides out two consecutive transport or 5xx failures and gives up on the third, and the web conversation page polls it per turn; an observe row sends `revision.updated` only once it has a dashboard, which is when it succeeds.
  `GET /api/v1/observe` lists the caller's own requests (any source, `source` filter, newest first, 20 per page by default), and `/dashboards/{id}/revisions` includes the observe request that created the dashboard (its `base_version` is null).
  `GET /api/v1/agent` tells clients whether an agent is configured and which provider, model and (Anthropic only) effort it uses.
- Comments: anchored to `(dashboard, version, panel_id)` or to the whole dashboard (`panel_id` null, `panel_present` true), never moved when panels change (`panel_present` tells clients); replies are one level (`parent_id`, a reply to a reply joins the root's thread) and copy the root's version and panel; status lives on the thread's first comment, replies mirror it, and `PATCH` on a reply changes the thread; resolve and reopen are idempotent `PATCH` status changes that send `comment.updated` only when the status really changed; `resolved_by_version` must lie between the thread's version and the dashboard's latest, is stored only when a call changes the status to resolved, and is cleared on reopen; `comment.created` carries `parent_id` for replies; `revision` holds the latest agent request for the comment (null when none was requested); event payloads carry ids and a capped author name, never comment text, so they stay far below the 8000 byte `pg_notify` limit.
  Comment lists page by `(created_at, id)` with `created_at` taken at insert, so a comment that commits after a later one was already listed can be missed by a client paging at that moment, and a fresh listing or its `comment.created` event recovers it.
- Query proxy: panel data is `GET /api/v1/dashboards/{id}/versions/{version}/panels/{panel_id}/data`; it runs every visible query of the panel in one request (at most 4 at a time, a hidden query never runs), tags each frame with its query's ref, caps `max_data_points` by the panel's `maxDataPoints`, raises a query's step to its own or the panel's `interval` (a duration, or `${name}` resolved from that interval variable's selection, `$__auto` included) and multiplies it by the query's `intervalFactor`, and fails as a whole with the failing query's `ref` in the error body; it accepts no query text (403 `query_not_in_spec`), aligns ranges to the step, caches successes for 10 s in process, limits each principal to 8 in-flight requests, and returns time values as epoch milliseconds.
  Relative times resolve in the dashboard's zone (the browser's, sent as `tz`, for `browser`) with its week start, fiscal year start and now delay; `spec/examples/time/resolve-cases.json` keeps Go and TS in step.
  A version whose queries reference `${__user.*}` is cached per principal, because the caches are otherwise shared by everyone.
  Variable selections are repeated `var-<name>` parameters: `$__all` selects All, custom and datasource variables accept only their values, a constant only its value, an interval variable an option or `$__auto`, a textbox one value, and an adhoc variable `key|op|value` filters; All expands to the full value list, or to `allValue` without a format when one is set.
  An interval variable with `auto` and no `default` defaults to `$__auto`, as in Grafana (the schema forbids writing `$__auto` as a `default`); without `auto` it defaults to its first option.
  Variable value lists are served by `GET .../variables/{name}/values`, and `POST /api/v1/datasources/{uid}/lint` parses a query without running it.
  `POST /api/v1/datasources/{uid}/preview` runs a draft data panel (`dashboard_id`, `version`, `panel_id`, `panel`, optional `from`, `to`, `max_data_points` and `variables`) placed into that saved version with `spec.WithPanel`, and answers 403 `user_session_required` to a bearer key; the draft must keep the id `panel_id` and name the datasource in the path for the panel and for every query that overrides it, a Spec problem is a 422 `invalid_spec` with issues, the queries run with `DraftLimits` under a 20 s deadline (`DraftLimits.Timeout` plus `DraftGrace`), the response is the panel data shape with `cached` false, and nothing is cached or coalesced.
  `GET /api/v1/datasources/{uid}/metrics`, `/labels` and `/labels/{name}/values` serve names to the browser through `Runner.Names`, the same validation, limits and upstream slot as the `list_metrics`, `list_labels` and `list_label_values` tools, waiting at most 5 s for that slot before `queryproxy.ErrUpstreamBusy` (429 `too_many_requests` with `Retry-After` on the routes, the same code in the tools); they count against the per-principal in-flight limit and are never cached; ClickHouse labels need `table`, or a `metric` whose `otel_metrics_*` table the adapter finds.
  `Datasource.Lint` returns an error, not a warning diagnostic, when the datasource is unavailable or times out, so the lint endpoint answers 502 `datasource_unavailable` or 504 `query_timeout` and the editor shows "Lint is unavailable right now."
  The proxy's runner is built with `queryproxy.WithValueCache()`, which caches query-variable value lookups for 10 s and coalesces concurrent identical ones; the runner that validates saves stays uncached, and both share the 32-call semaphore.
  A malformed query string is a 400, and a forbidden parameter name is a 403 even when its value is malformed.
  Coalesced calls run on a shared context that is canceled when the last waiting caller leaves, and lint takes the process-wide upstream slot like any other datasource call.
  The proxy caches stay near 88 MiB: panel data 64 MiB, variable value lists 8 MiB (1 MiB per entry), and the runner's value lookups 16 MiB.
  Never log query text or variable values.
- Datasources: adapters live in `internal/datasource/{prometheus,clickhouse}` behind `datasource.Datasource`, and `internal/datasource/provision` builds the registry from `config.Datasources`.
  Variable values reach queries only through `internal/datasource/macros`.
  An adhoc variable applies itself to every Prometheus query on its datasource as extra label matchers, and a ClickHouse query uses it explicitly as `$name` in a WHERE clause. Grafana's ClickHouse plugin applies adhoc filters without `$name`; SlashObserve does not in milestone 2, and the importer lists the queries a ClickHouse adhoc variable will not filter.
  ClickHouse is queried only as a `readonly = 2` user with `SELECT` on the OTel database, and the server refuses a user that is not read-only.
  `GET /api/v1/datasources` returns health, `checked_at` and `dashboard_count` (dashboards whose latest version uses the uid), never a URL, address, user or secret, and datasources never gate `/readyz`.
  The health `message` is a fixed plain-language string chosen by error kind, never the error's own text.
  A Spec names a datasource by uid, or as `${name}` naming a datasource variable (a panel, a query, a query variable or an adhoc variable; a variable must come after the datasource variable it names, and `spec.DatasourceVariableName` is the only parser); the query proxy runs such a query on the datasource selected in that variable, and a datasource variable's `default` is always a uid.
  A literal uid's type comes from the registry and a `${name}` reference's from the variable's `datasourceType`, so the query proxy, not `spec.Parse`, rejects a macro that the type does not have (`unknown_macro`).
- Logging: `log/slog`, JSON by default; request logs record the path, never the query string.
  The server never logs secrets, prompt text, query text or tool results, so a failure is logged as a fixed message plus `logattrs.Failure(code, err, ids...)` (`error_code`, `error_type`, `sqlstate`) and the relevant ids, never `err.Error()`, and a panic by its type only.
  `sloglint` (in `make lint`) forbids the literal attribute keys `error` and `err` in slog calls under `internal/`, `cmd/` and `pkg/`, tests included; `internal/logattrs` is exempt, and `demo/` is out of scope.
  It cannot see a key built through a variable or a helper, or `err.Error()` under another key, so review those by hand.
  A fatal startup error keeps its text only through `described` in `cmd/slashobserve-server/main.go`, for messages the server wrote from settings (never echo a URL setting); driver, DSN and library causes are reduced to `error_code`, `error_type`, `sqlstate` and `errno`, plus ids the server owns (`db_host` and `db_port` parsed from the setting, `datasource_uid` and the datasource's own `ConfigError` text from `provision.BuildError`, `migration_version`).
  A request the client abandoned is not a server failure, and a cancellation on a live request context still is: handlers pass the error through `clientgone.Handle` before logging at ERROR or answering 500, and the access log then shows status 499 with `bytes` 0, also under the API contract check.
  `internal/logtest` captures a logger for tests (`AssertSafeFailure` checks the code and type and that the error text is absent).
- API contract: every `/api/v1` route is documented in `api/`.
  The e2e stack runs with `SLASHOBSERVE_API_CONTRACT_CHECK=true`, which refuses to boot on undocumented routes (or documented operations with no route) and turns any request or response that breaks the document into a 500 `{"error":"api contract violation","code":"contract_violation"}`.
  A request that breaks the document is allowed only when the handler refuses it with a 4xx.
  `scripts/e2e.sh` fails when the server log contains `api contract violation`.
  Document every status a handler can return, and keep `additionalProperties: false` on response objects so new fields must be documented.
  Wire conventions for `/api/v1`: JSON field names are `snake_case` (the Spec document inside a response keeps its camelCase), times are RFC 3339 UTC strings, errors are `{"error","code"}` plus optional fields named per endpoint, and lists use opaque `cursor` and `next_cursor` (null at the end) with `limit`.
- Spec defaults live in `spec/schema/defaults.json` (`spec.Defaults()`): the `dashboard` section (`cursorSync`), per-type `display` defaults, `canvasElement` and `canvasConnection` defaults and `instantPanels` (`spec.InstantByDefault`, read by Go and the web); an absent value means that default, the importer drops values equal to it, and renderers read the same file.
- Design: prefer deep modules (small interface, real behavior behind it); accept dependencies instead of creating them; add a seam only when two adapters exist.
- ClickHouse in compose has a read-only user `slashobserve_ro`, created on first boot by `deploy/compose/clickhouse/initdb/10-readonly-user.sh` from `internal/datasource/clickhouse/testdata/readonly_user.sql` (`readonly=2` with constraints), the same definition the integration tests use.
- Any feature that fetches a URL taken from user content goes through `egress.Client`, never its own `http.Client`.
- Integration tests run against real Postgres, Prometheus and ClickHouse through testcontainers, never mocks.
- Write no docstrings or comments unless they state a constraint the code cannot show.

## Frontend conventions

- Bun is the package manager and script runtime; `web/bunfig.toml` forces the Bun runtime for every `bun run` script.
  Node and pnpm are not used.
- React 19, TypeScript strict, Vite, Tailwind CSS v4, shadcn/ui on Base UI (`components.json` style `base-nova`), TanStack Router with file-based routes.
- Add shadcn components with `bun x shadcn add <name>` from `web/`; they live in `web/src/components/ui`.
- `web/src/components/ui` primitives are restyled to the M1 rules, and every `bun x shadcn add` must be restyled the same way before commit: controls `rounded-control` and 32px high (`h-8`) with 13px text, popups and dialogs `border border-border` with no shadow, ring or backdrop blur, badges never pill-shaped, and focus a solid 2px `ring-ring` (brand blue).
  Workspace pages are built from `PageHeader`, `TableCard` (`HeaderCell`, `Cell`), `StatusLabel` (icon plus word, tones `ok|warning|critical|running|none`) and `RelativeTime` (`formatShortRelative`: "12 s ago", "Yesterday", "In 74 days"; its shared clock ticks every second while a mounted one shows an offset under a minute, else every 30 s) in `web/src/components`.
  Import `cn` only from `@/lib/utils`: it is configured with the custom `control` and `card` radii, so `cn("rounded-control", "rounded-full")` keeps one; a `bun x shadcn add` file that imports `cn` from `cn` gets rewritten to `@/lib/utils` in the same restyle.
- `web/src/routeTree.gen.ts` is generated by the Vite plugin on `dev` and `build`; commit it, never edit it.
- `web/src/spec/*.gen.ts` are generated from the schema by `make generate` (commit them, never edit); import only from `web/src/spec/index.ts`, and keep that folder free of app imports so it can become the `@slashobserve/spec` package.
  `web/src/spec/panels.ts` holds the pure panel helpers (`allPanels`, `findPanel`, `isDataPanel`, `queryRef`).
- `web/src/spec/defaults.gen.ts` is generated from `spec/schema/defaults.json`, the defaults contract shared with the Grafana importer: an absent value means that default, so renderers read options only through `displayWithDefaults` and the other accessors in `web/src/spec/defaults.ts`, never with their own fallbacks; parity tests on both sides keep the copies equal.
- `web/src/api/schema.gen.ts` is generated from `api/openapi.yaml` by `make generate` (commit it, never edit); `make lint` fails when it is stale.
- A new glob-loaded or script entry point goes into `web/knip.json` `entry`; code nothing imports is deleted rather than ignored, and only vendored `web/src/components/ui` and generated files are ignored there.
- Formatting follows shadcn's Prettier style (no semicolons, double quotes); `bun run format` before committing.

- Histograms bucket every finite value of every visible number field across the range (20 equal buckets unless `bucketSize` or `bucketCount` is set; `bucketSize` aligns edges to its multiples and wins over `bucketCount`; at most 1,000 buckets; the last bucket includes the maximum) and stack the series by color.

- Stat tiles follow the design canvas: one per visible number field, value from `display.reduce`, text and color from `displayValue`; each draws the value at a fixed 28px in the foreground color with the unit as a separate muted 13px span, a state row (threshold icon plus word, always shown when thresholds are set and text is on) and a 32px sparkline edge to edge at the bottom.

- Bar gauges draw one bar per visible number field, reduced by `display.reduce`, horizontally as a 13px name and value line over an 8px full-width muted track filled in the resolved color (else `--series-1`); a field's range is its own `min` and `max`, else 0..100 for `percent` and 0..1 for `percentunit`, else from the lower of 0 and the smallest value to the largest (an empty range widens by one), and `orientation: auto` follows the body's aspect (horizontal when wider than tall).

- Bar charts are SVG with HTML labels: the categories come from `xField`, else the first text field, else the first time field, with frames joined on it; every other visible number field is a bar series in its threshold, mapping or palette color; fields with the same `stack` mode stack; `orientation: auto` is horizontal when the body is taller than wide; at most 500 categories.
- Values that appear together (a table column, stat tiles, bargauge rows, tooltip rows, axis ticks) share one decimal count from `commonDecimals` in `web/src/lib/units.ts` (`decimalsByUnit` there groups it per unit for gauges, bar gauges, pie charts and table columns), so `2.40` and `2.45` never mix with `2.4`.
  The count is capped at about four significant figures of the largest value, so tiny values next to large ones round instead of widening every value; axis ticks (`axisDecimals`) widen past the cap until neighbouring ticks read differently, and a threshold label never rounds below the threshold's own decimals.
- Pie charts are SVG, one slice per visible number field by `display.reduce`, colors from the series palette unless a field color, mapping or threshold sets one, with values and percentages in the legend rather than on slices; null, zero and negative values are left off the pie and listed in the legend.
- Geomaps draw markers over Natural Earth country outlines bundled from `world-atlas` (110m, Web Mercator, outlines only, no fills) and never load map tiles or any other third-party resource; locations come from lat/lon or geohash fields, marker size from `sizeField` between `markerSize` and `markerSizeMax`, color from `colorField`'s threshold or mapping color.
- Gauges are SVG meters (`role="meter"` on a non-interactive wrapper, with links outside it, and `aria-valuenow` clamped into the range and the raw value in `aria-valuetext`), one per visible number field, ranged by field `min`/`max`, else 0 to 100 for `percent` and 0 to 1 for `percentunit`, else the data (0 or the data minimum, up to the data maximum across every visible field), with threshold markers as a thin outer ring.
  The cells form the grid with the largest square cells that fits the panel body (`gaugeGrid`), so a gauge never scrolls.
  The arc and ring take their colors from CSS variables, so a theme change needs no re-render, and the value text stays in the foreground color; the threshold icon is threshold-colored next to its word, and a mapping whose color wins over the threshold drops the threshold word and icon.

## End-to-end tests

- Two suites: `scripts/e2e.sh`, curl-driven checks against the compose stack (API, MCP and CLI), and Playwright in `web/e2e` (Chromium, one worker, retries only in CI).
- The CI `e2e` job is skipped until the suite is stable on GitHub runners, so the suites run locally at integration.
- Playwright specs import `test` and `expect` from `web/e2e/fixtures.ts`, which fails any test whose page logs a console error.
- The Playwright `setup` project (`web/e2e/auth.setup.ts`) signs in through Dex once and saves `web/e2e/.auth/user.json`.
  Every `chromium` spec reuses that session, and a spec that signs out must opt out with an empty `storageState` and sign in itself.
- The e2e stack is compose project `slashobserve-e2e`, reset with `down -v` on every `make e2e`, on host port 18080 (`SLASHOBSERVE_E2E_PORT`), so it never touches a developer's `make demo` stack.
  `scripts/e2e.sh` run, up, browser and down hold an exclusive kernel `flock` on `/tmp/slashobserve-e2e-run.lock` (a fixed path, because `TMPDIR` differs between shells and agents) for their whole run, and write their pid into it, so two invocations never reset the same stack; a second one fails at once with "another e2e run is active (pid N)", or with "cannot open /tmp/slashobserve-e2e-run.lock" when `/tmp` is not writable.
  The kernel drops the lock when the script exits, even after a crash, so there is nothing to clean up by hand; the file itself stays.
  Do not remove or rename the lock file while a run is active.
  After a kill -9, leftover child processes of the dead script can still hold the lock: it clears within seconds, or up to 90 seconds if the script was killed during an API call, and meanwhile the message says "pid N exited; a leftover child still holds the lock, retry shortly".
  A directory at that path, left by an older `scripts/e2e.sh`, fails with "stale directory from an older e2e.sh"; `rmdir` it.
  A symlink at that path fails with "is a symlink"; the script never follows one.
  SIGINT, SIGTERM and SIGHUP run the same cleanup and exit 130, 143 and 129; a script started in the background by a non-interactive shell ignores SIGINT, so stop it with SIGTERM.
  Every `docker compose exec` in the script uses `-T` with stdin from `/dev/null` (an inherited stdin once hung a run for 29 minutes), and `exec` (60 seconds), `ps` (30 seconds) and the failure `logs` dumps (30 seconds; 120 seconds for `scripts/e2e.sh logs`, which CI uploads as an artifact) run under a small perl wrapper in their own process group, since macOS has no `timeout`; `docker compose up` and `down`, `bun run e2e:install` and the Playwright run use the same wrapper without a timeout, so an interrupt stops the whole process tree.
  Polls run their commands in the main shell with output in files, so a signal is handled at once; a failed poll prints the last stderr of the command it polled, and every failure message and compose log dump, including `scripts/e2e.sh logs`, passes through a redaction filter for tokens, cookies, passwords and URL credentials (numeric token counts such as `"input_tokens":42` stay readable); the live output of `docker compose`, `bun` and Playwright is not filtered.
  The e2e stack also publishes Prometheus on 19090 (`SLASHOBSERVE_E2E_PROMETHEUS_PORT`) and the shop fault API on 18081 (`SLASHOBSERVE_E2E_SHOP_PORT`).
  CI builds the server image once as `slashobserve-e2e:ci` and the shop image as `slashobserve-demo-shop:ci` (`SLASHOBSERVE_SHOP_IMAGE`), and uploads Playwright traces, videos, the HTML report and compose logs when a test fails.
- `scripts/e2e.sh` boot waits, with bounded polling, until Prometheus has scraped every target and ClickHouse has log and trace rows, so later checks start on a stack that is already exporting; checks on telemetry that may still be arriving poll instead of asserting once.
  The shop contract (pods, routes, metric labels) is shared by the Prometheus backfill and the e2e checks, so change them together.
  The Prometheus entrypoint picks the backfill's `end` 20 seconds after it starts (generating and importing the backfill takes 5 to 8 seconds on an idle host) and writes it to `/prometheus/backfill-end`.
  The entrypoint removes any old `backfill-end` first, so the load generator waits for the new one.
  It regenerates when generation finishes less than 7 seconds before `end` (as on a CPU starved host) or when it finds a stale `.ready` from an earlier start whose `end` is not the one still published in `backfill-end` (when it is, a load generator may already be running on it, so the entrypoint reuses those blocks and that `end` instead of moving it), with a lead of twice the time the last try took plus 10 seconds, capped at 55 seconds because the load generator starts at once when `end` is more than its one minute `maxStartLead` away and would double count the backfill (`demo/shop/internal/loadgen/loadgen_test.go` fails when the two drift apart).
  It stops retrying after 4 tries or 90 seconds in total and warns that the junction will show a gap, so boot usually stays inside the Prometheus healthcheck window of about 210 seconds; a loaded host therefore boots later instead of starting Prometheus and the load generator after `end`, which would leave a gap of the missed seconds in the junction.
  The load generator mounts that volume read-only (`LOADGEN_START_FILE`), waits for the file and sends its first request exactly at `end` (or at once if `end` is more than a minute ahead), so it does not depend on Prometheus being up.
  Business counters and histograms are created on the first business request, so a live counter counts requests since `end` and the junction is a counter reset that neither double counts nor loses requests.
  Prometheus starts 5 seconds before `end`: its first shop scrape comes 5 to 10 seconds after it starts, so the first live sample lands at most about 5 seconds after `end` (a scrape before `end` would be dropped as out of bounds).
  A 1 minute `rate()` whose window starts after `end` still misses the requests before its first live sample, less what Prometheus extrapolates, so the junction shows a small dip.
  `backfill_joins_live` in `scripts/e2e.sh` compares, per `service`, `route` and `pod` above 1.5 requests per second, the 1 minute request rate and p95 around the junction with their values 35 seconds before `end`, and requires every 5 second sample from 30 seconds before to 90 seconds after `end` to stay within 0.85 to 1.15 for the rate and 0.95 to 1.6 for the p95.
  Every route's 95th percentile must sit inside a well populated histogram bucket whose upper edge is far above the slowest latency the route can produce, or CPU starvation (sleeps overshooting) moves it across the bucket: frontend `/api/products` used to sleep 5 to 25 ms, which put its p95 on the 25 ms edge and let it reach 1.7 on a loaded host.
  The p95 bucket must also hold at least 40% of the requests of every route the check covers, because a histogram quantile is interpolated inside its bucket and a thin bucket turns sampling noise and timer overshoot into p95 movement.
  With `F` the share of requests below the bucket, `n` the requests in the 1 minute window and nothing above the bucket, p95 is the lower edge plus the width times (0.95 - F) / (1 - F), its slope in `F` is the width times 0.05 / (1 - F)^2, and `F` has a standard deviation of sqrt(F (1 - F) / n); the backfill side has no noise.
  With every covered route above 40%, the 0.95 floor sits clear of that sampling noise instead of inside it.
  The profiles in `backfill.awk` are calibrated from the shop containers alone (`docker run`, 30 requests per second, 6 minutes), and the highest bucket of each profile is the diurnal tail that is zero at the junction.
  Per route at the junction, the share of requests in the p95 bucket, that bucket, and the slowest latency the sleeps allow (including about 1 ms of overhead):

  | Route | Sleeps | p95 bucket | Share in bucket | Slowest latency |
  | --- | --- | --- | --- | --- |
  | frontend `/api/products` | 10 to 35 ms | 25 to 50 ms | 43% | 36 ms |
  | frontend `/api/products/{id}` | 10 to 35 ms | 25 to 50 ms | 43% | 36 ms |
  | frontend `/api/orders/{id}` | 2 to 5 ms and 5 to 30 ms | 25 to 50 ms | 45% | 38 ms |
  | checkout `/orders/{id}` | 5 to 30 ms | 25 to 50 ms | 30% | 31 ms |
  | payments `/charge` | 30 to 70 ms | 50 to 100 ms | 52% | 72 ms |
  | checkout `/checkout` | 20 to 40, 30 to 70, 20 to 40 ms | 100 to 250 ms | 75% | 153 ms |
  | frontend `/api/checkout` | 2 to 8 ms plus checkout | 100 to 250 ms | 85% | 162 ms |

  Changing a sleep range changes its row, the rows of every route that calls it, and the profile in `backfill.awk`, so recalibrate them together.
  The p95 band stays wide above (1.6) and tight below, where a gap or a double count would show.
  The check waits until the window ending 90 seconds after `end` is 10 seconds old, then judges it once: a band violation fails at once with the series outside each band and its value (`query failed` when the re-query broke, `none on re-query` when it found none), next to the loadgen's dropped count, instead of polling out the full timeout.
  The `/orders/{id}` routes are left out because their low request rate swings the rate on seeded traffic alone.
  The backfill rates equal the load generator's steady state at the junction and the diurnal shape has zero offset and slope there.
  The sample spacing grows geometrically from 5 seconds at `end` to 30 seconds going back, and every timestamp carries milliseconds: whole-second spacing makes `rate()` extrapolation dip on the sparser samples.
  The cAdvisor job sets `honor_timestamps: false` because its `machine_*` series carry a fixed explicit timestamp from cAdvisor's start, which falls before the backfill's end and would be dropped as out of bounds, and cAdvisor runs with `--housekeeping_interval=5s` so every 15 second scrape sees counters of the same age and `rate()` over `container_cpu_usage_seconds_total` does not step.

  A revise fixture may leave `dashboard_id` and `parent_version` out of `update_dashboard`, so it never depends on generated ids; a comment or prompt with no fixture fails its revision with `model call failed: no replay fixture`.
  Comments queue a revision only with `"request_revision": true`.
  `evals_smoke_suite` runs the eval runner on the scenarios tagged `replay-smoke` (`red-metrics-by-endpoint`, `log-volume-by-service`) and expects every check to pass, so those two prompts need fixtures.
  The runner exits 1 when the pass rate is below `--min-pass` (0.8) or, with all 10 `done_when` scenarios run, fewer than `--min-done-when` (8, or the number of `done_when` scenarios in a custom folder when fewer) pass, and 2 on a usage or setup error.
  Observe fixtures cover the brief's broken-query repair path (`observe-red-metrics.json` saves a query with an unbalanced parenthesis, gets `query_invalid`, and repairs it).
- Compose: add new services (Dex, Prometheus, ClickHouse, OTel Collector, demo/shop) to `deploy/compose/compose.yaml`; publish host ports only for what a browser or developer must reach, bound to 127.0.0.1 with a `${...}` override.
  Only `frontend-0` builds the shop image (`pull_policy: build`), so a plain `docker compose up` rebuilds the image named by `SLASHOBSERVE_SHOP_IMAGE` even when it is prebuilt; pass `--no-build` to keep it.

## Product rules

- The agent only ever outputs ObserveSpec JSON; no code path takes LLM-written HTML or JS into the UI.
- Text panels render Markdown with `react-markdown` (`skipHtml`, no `rehype-raw`), variable values escaped before parsing, and links and images limited to http(s), mailto and same-origin URLs; placeholder panels show their importer reason.
- Datasource credentials never reach the browser; all panel data goes through the query proxy, which only runs queries from a saved Spec, except `POST /api/v1/datasources/{uid}/preview`, which runs a signed-in user's draft panel placed into a saved version, with the agent tools' limits, never cached and counted against the caller's in-flight limit.
- Every query the agent runs is time-bounded and limited (series, rows, points, timeout) on the server, whatever the prompt says.
- Tools are defined once in `internal/agent/tools`; MCP and the built-in agent share them, except the comment tools, which are MCP-only.
- The agent's text output is discarded; only tool-saved Specs, or in suggest mode one tool-validated panel, leave a run.
- The agent never creates or edits placeholder panels; they come from Grafana imports.
- Imports are the one tolerant first save: `POST /api/v1/imports` saves version 1 even when queries fail and records those panels and variables in `version.unverified` and the import report.
  Later saves run every query; a failing panel or variable is kept only while the parent version lists it as unverified and it is unchanged (see Dashboards), and the agent is told never to delete an unverified panel unless asked.
  The original Grafana JSON is stored in `imports.original` and is never returned by the API or shown to the agent.
- Every Grafana built-in panel type is a Spec type, an import-time mapping onto one, or a placeholder with a stated reason (`annolist`, `welcome`, `gettingstarted`, `debug`, `live`, `alertGroups`).
- Anything Enterprise will extend goes behind an interface in `pkg/extension`; core never imports Enterprise code.
- `razorpay/slashdocs` is a reference, not a dependency: never import its packages or copy whole files; credit any verbatim snippet in `NOTICE` under its MIT license.

## Workflow

- Make atomic commits: one self-contained change that builds and passes on its own; messages describe the change only, with no task numbers or co-author trailers.
- A user-visible change updates the `docs/` page that describes it in the same commit; slashobserve.com builds its docs from `docs/` on `main`.
- Do not commit ADRs, decision records or the brief; decisions live in this file, and implementation plans live outside the repository.
- Create repositories, push, and open PRs only after Ishan says go.
- CI branch protection must mark the `check` job as required, and `e2e` once that job is re-enabled.
- Markdown: one sentence per line; never use an em dash.
